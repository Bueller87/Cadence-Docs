# Cadence vs Dapr for agentic AI workflows

**Internal assessment · November 19, 2026**  
**Scope:** Cadence platform, SDKs, and `cadence-ai-samples` together, compared with Dapr runtime and Dapr Agents. Focus: building, understanding, and running agents.

**Takeaway:** Dapr packages more of the agent application experience: tools, hosting, memory, and tracing. Cadence already combines durable execution with familiar agent frameworks and useful samples. The clearest opportunities are integration coverage, simpler learning paths, and support clarity; this review does not establish a missing core durability capability.

## At a glance

“Integration gap” means a supported, documented path was not found in the reviewed SDK and sample surfaces. It does not mean Cadence cannot execute the operation.

## Three proposed priorities

1. **Make the smallest complete agent the learning path.** Start with Human in the Loop, then link Incident Triage's recovery rehearsal. Reuse the Explorer and templates. Keep agent decisions readable apart from setup and presentation code. Measure whether a newcomer can run, explain, and modify it.
2. **Add focused integration recipes.** Start with MCP, then conversation memory and retrieval using existing frameworks and stores. Preserve independently copyable recipes. Show which operations run as Activities, what survives a restart, and how repeated external writes are handled.
3. **Make support and debugging explicit.** Consolidate the tested Python/framework/provider combinations, explain Git pins, and distinguish mock coverage from live verification. Add one tracing walkthrough connecting an agent run, model call, and tool call to its Cadence execution.

Cadence's clearest positioning is **familiar agent frameworks running within a shared, inspectable workflow platform**. Demonstrate durable human waits, failure recovery, and operator controls in one understandable story. Dapr also provides durable agents; these capabilities alone do not establish superiority.

## Caveats

- Source review, not a usability study or execution test. No performance, reliability, cost, or popularity ranking was measured. Priorities above are proposals.
- Workflow history is not conversation memory or retrieval. Dapr's memory abstraction also requires an appropriate backend; its default list memory does not establish cross-process persistence.
- Compare specific integrations: Dapr also documents LangGraph checkpoint and Strands session extensions, with different semantics from durable agent execution. Generic Workflow SDK language counts do not establish agent-framework parity. [D2]
- Dapr still needs its runtime and backing services. Its `MCPServer` resource uses an alpha API version. The Dev Dashboard explicitly targets local development; Diagrid's production console is a separate offering. [D2][O1]
